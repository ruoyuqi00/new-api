# User Ticket Center Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a private user/admin ticket center with multi-turn replies, manual-refund categorization, and secure attachments.

**Architecture:** Store tickets, append-only messages, and private attachments in separate GORM models. Expose ownership-scoped user endpoints and existing `AdminAuth` endpoints, with one transaction for every message/status update. Add additive React routes and i18n strings using the current branded `web/default` components; leave balances, billing, logs, and existing navigation intact except for the new ticket entries.

**Tech Stack:** Go 1.22+, Gin, GORM v2, existing auth/rate-limit/JSON wrappers, private filesystem storage, React 19, TanStack Router, TanStack Query, Base UI, Tailwind, Bun, and i18next.

**Spec:** `docs/superpowers/specs/2026-08-31-ticket-center-design.md`

## Global Constraints

- The refund category is communication only; never credit balance, create a refund transaction, or change billing records automatically.
- Users can access only their own tickets; administrators use existing `AdminAuth`.
- Messages are append-only and preserve author role and creation time.
- Closed tickets are read-only for users; admins can reopen.
- Append message, status, timestamps, and unread counters in one transaction.
- Attachments stay outside public static paths and require ticket ownership/admin authorization for download.
- Reject empty content, invalid enum values, path traversal, unsupported MIME types, and oversized files.
- Do not write ticket bodies, attachments, storage keys, API keys, or tokens to access logs.
- Use GORM for SQLite, MySQL >= 5.7.8, and PostgreSQL >= 9.6; do not add dialect-specific SQL.
- Use `common.Marshal`/`common.Unmarshal` wrappers for new JSON operations.
- All new user-facing strings must use `useTranslation()` and locale files.
- Work in the isolated production-derived worktree; do not change production, Caddy, or existing balances.
