# YuAPI 视频 API 新手文档与管理员示例素材设计

日期：2026-08-16

状态：已确认设计，待实施计划

范围：公开视频 API 文档、文档页语言切换、脱敏截图、管理员私有示例素材导入、热切换上线验证

## 1. 背景

生产环境的视频模型、公开价格和任务协议已经完成更新，但当前公开文档仍偏向已有 API 使用经验的开发者，缺少从登录站点、创建 API Key 到首次成功生成视频的完整路径。现有文档还包含不应对外出现的内部来源、成本和转发语义，需要彻底清理。

本次同时保留此前真实探测生成的 10 个视频文件，并将它们作为管理员私有示例素材导入 YuCore Studio 画布素材库。导入不得公开这些视频，不得接触普通用户素材，也不得删除或重新编码原始文件。

## 2. 目标

1. 让第一次使用 API 的用户可以仅依赖公开文档完成：创建 API Key、验证 Key、创建 `seedance-2.0` 视频任务、轮询任务和下载结果。
2. 提供简体中文、繁体中文和英文三份内容完整、技术事实一致的文档。
3. 在文档页面提供独立语言切换，不扩大为全站繁体中文改造。
4. 公开内容只描述 YuAPI 对外合同，不暴露任何内部来源、账号、渠道、成本、加价规则、容量观测或转发实现。
5. 将指定的 10 个真实测试视频按原始字节导入管理员私有的“视频模型示例”集合，并允许拖入画布使用。
6. 所有变更通过并行候选容器和稳定网络别名热切换上线，不停止当前生产容器。

## 3. 非目标

1. 不为全站新增 `zh-TW` 语言包。
2. 不改动视频模型协议、计费算法或生产价格。
3. 不公开测试视频，也不在公开文档中嵌入或链接这些视频。
4. 不导入任何用户生成内容。
5. 不重新生成、转码、压缩或重命名原始测试文件。
6. 不新增通用公共素材市场或跨用户共享素材能力。
7. 不把内部来源配置、真实凭据或生产观测数据写入 Git。

## 4. 已确认的产品决策

### 4.1 文档组织

采用三份独立 Markdown 文件：

- `web/default/public/developer-docs/yucore-api.md`：简体中文，并继续作为兼容旧链接的默认文档。
- `web/default/public/developer-docs/yucore-api.zh-TW.md`：繁体中文。
- `web/default/public/developer-docs/yucore-api.en.md`：英文。

不采用单个超长多语言 Markdown，也不引入内容生成器。三份文档允许针对语言调整表达，但通过自动化检查锁定模型、价格、路径、参数和状态等技术事实。

### 4.2 文档页语言选择

`web/default/src/features/docs/index.tsx` 增加文档专用分段选择控件：

- 简体中文
- 繁體中文
- English

选择算法按以下优先级执行：

1. 若本地存储中已有用户手动选择，则使用该值。
2. 否则先尝试映射当前站点语言；仅 `zh-TW`、`zh-HK`、`zh-Hant`、其他 `zh` 和 `en` 视为可直接映射。
3. 当前站点语言无法映射时，按 `navigator.languages` 顺序尝试浏览器语言。
4. `zh-TW`、`zh-HK`、`zh-Hant` 映射到繁体中文。
5. 其他 `zh` 映射到简体中文。
6. `en` 映射到英文。
7. 仍无法映射时回退到简体中文。

手动选择保存在仅供该文档页使用的本地存储键中，不调用全站 `i18next.changeLanguage`。文档查询缓存键必须包含文档语言，切换时不得短暂显示另一语言的正文。

默认简体中文文件路径保持不变，避免旧书签、搜索结果或外部链接失效。

### 4.3 文档信息结构

三份文档使用相同的章节顺序：

1. 开始前：区分网页登录账号、API Key 和任务 ID。
2. 注册或登录并确认账户可用。
3. 创建第一个 API Key。
4. 使用 `/v1/models` 验证 Key。
5. 用 `seedance-2.0` 创建第一个视频任务。
6. 保存任务 ID 并轮询原任务。
7. 下载生成结果。
8. 将测试 Key 调整为生产安全配置。
9. 完整视频模型与公开价格表。
10. 视频任务请求和响应协议。
11. 模型参数、素材数量、时长、分辨率和音频能力。
12. Windows PowerShell 示例。
13. macOS/Linux `curl` 示例。
14. 完整 Python 示例。
15. 高级 Node.js/JavaScript 示例。
16. 状态、错误处理、重试和支持信息。
17. 上线前检查清单。

图片相关既有内容可以保留在参考部分，但视频新手路径必须位于文档首屏后的主要位置，不能被图片说明打断。

### 4.4 API Key 新手说明

文档必须明确：网页登录密码不能作为 API Key，API Key 也不用于网页登录。创建流程从站内 `/keys` 页面开始，并使用该页面当前真实可见的控件名称。

首次测试配置：

- 名称示例：`video-quickstart`。
- 分组选择：`多模态创作`。
- 可以暂时沿用默认有效期和额度配置。
- 建议开启模型限制并只允许 `seedance-2.0`，但不得把该建议写成接口强制要求。

生产安全配置：

- 设置符合业务周期的有效期。
- 设置可接受的额度上限。
- 只允许业务实际使用的模型。
- Key 只保存在环境变量、服务端密钥管理或受控配置中。
- 禁止把 Key 写入浏览器前端、公开仓库、工单正文或截图。
- 泄露后立即删除或禁用旧 Key，并创建新 Key。

`下游多模态` 只在高级说明中出现，明确它不适合普通首次接入用户。文档不得描述该分组的内部来源或路由方式。

### 4.5 首次视频示例

首次示例固定使用 `seedance-2.0` 和纯文本提示词，不要求参考图片、视频或音频。示例流程必须完整覆盖：

1. 设置 `YUAPI_API_KEY` 环境变量。
2. 请求 `GET /v1/models` 验证 Key 和基础地址。
3. 请求 `POST /v1/videos` 创建任务。
4. 从响应中读取并立即保存任务 ID。
5. 使用 `GET /v1/videos/{task_id}` 和同一任务 ID 轮询任务状态。
6. 成功后通过 `GET /v1/videos/{task_id}/content` 下载文件。
7. 失败后保留任务 ID、请求时间、模型 ID 和完整错误消息。

文档必须醒目标明：客户端超时或任务仍在处理中时，不得重新发送创建请求；应继续查询原任务，避免重复扣费和重复生成。

各平台示例：

- Windows 使用 PowerShell 原生命令和环境变量语法。
- macOS/Linux 使用 `curl` 和 shell 环境变量。
- Python 示例为可直接运行的完整脚本，包含创建、有限次数轮询、终态判断和下载。
- Node.js/JavaScript 示例放在高级章节，使用服务端环境，不暗示在浏览器中暴露 Key。

所有示例使用虚构 Key、虚构任务 ID 和不含真实用户信息的提示词。

## 5. 管理员私有示例素材

### 5.1 文件范围

只导入已经完成并保存在受控本地源目录中的 10 个 `.mp4` 文件。源目录位于 Git 工作区外，由上线命令通过显式参数传入；代码、配置和提交记录不得硬编码工作站绝对路径。

文件集合：

- `happyhouse-1.0.mp4`
- `happyhouse-1.1.mp4`
- `minimax-h3-2k.mp4`
- `omni-fast-no-water.mp4`
- `omni-fast.mp4`
- `omni-v2v-no-water.mp4`
- `omni-v2v.mp4`
- `sd7-seedance-2.0-1080p.mp4`
- `sd7-seedance-2.0-720p.mp4`
- `seedance-2.0.mp4`

原文件继续保留在原目录。生产导入只复制字节，不移动、不删除、不重命名、不转码。

### 5.2 数据建模

不新增数据库表。每个导入视频对应一条现有 `YucoreMediaTask` 已完成任务记录：

- `UserId`：执行导入的管理员用户 ID。
- `Kind`：`video`。
- `Status`：`completed`。
- `Progress`：`100`。
- `Cost`：`0`，导入不得扣减钱包额度。
- `ModelId`：由导入清单明确给出，与文件名对应。
- `Metadata.collection_id`：`video-model-examples`。
- `Metadata.collection_name`：`视频模型示例`。
- `Metadata.imported_sample`：`true`。
- `Metadata.sha256`：文件实际 SHA-256。
- `Metadata.original_file_name`：仅保存上述无敏感信息的文件名。

任务 ID 由固定前缀和 SHA-256 派生，例如 `yu_sample_<hash-prefix>`。数据库唯一任务 ID 和确定性文件名共同保证导入幂等，不依赖数据库方言特有的 JSON 查询。

### 5.3 导入接口和文件存储

增加管理员鉴权保护的内部样例导入接口：

`POST /api/yucore/media/admin/sample-assets`

接口使用 `multipart/form-data`，复用现有媒体上传的 MIME 嗅探、MP4 结构校验、大小限制和安全路径处理。只接受：

- `file`：一个视频文件。
- `model_id`：公开模型 ID。
- `sha256`：预期 SHA-256，使用 64 位十六进制格式。
- `collection_id`：只允许固定值 `video-model-examples`。

服务端写入同一用户目录下的临时文件，并在单次流式写入中计算实际 SHA-256。实际值与预期值一致后，才以原子重命名提交为确定性文件名并创建任务记录。校验失败时删除临时文件，不创建任务记录。

文件写入 `YUCORE_MEDIA_UPLOAD_DIR/<admin-user-id>/` 下的确定性安全文件名。持久化素材 JSON 增加只供服务端使用的站内托管文件引用；该字段不得出现在 `YucoreMediaAsset` 公共响应中，也不需要数据库迁移。任务资源响应只返回所有者保护的 `/api/yucore/media/tasks/{task_id}/assets/{index}` 地址；真实磁盘路径、签名和内部源描述不进入 JSON 响应。

任务素材处理器增加受限的“站内托管文件”分支：只有在任务所有者校验通过、当前用户仍具有管理员角色、文件归属目录与任务 `UserId` 一致、文件名通过安全路径检查时才读取文件。视频响应支持浏览器播放需要的 Range 请求，并返回私有缓存头。

导入接口使用 `AdminAuth`，写操作进入现有管理员审计链路。普通用户无法调用导入接口。

成功响应只返回 `created`、`task_id`、`asset_url`、`sha256` 和 `size`。若同一任务已经完整存在，则 `created` 为 `false` 并返回既有任务；不得返回磁盘路径。

提供对称的受保护回滚接口：

`DELETE /api/yucore/media/admin/sample-assets/{task_id}`

该接口只允许删除由样例导入流程创建、属于当前管理员且仍标记为 `video-model-examples` 的任务和托管副本。普通任务、其他管理员任务或缺少导入标记的任务一律拒绝删除。

### 5.4 Studio 展示

“我的素材”继续使用现有按 `user_id` 隔离的图库查询。当前管理员的图库响应中若存在由确定性样例任务 ID 和 `Metadata.collection_id = video-model-examples` 共同标识的素材，则展示独立集合“视频模型示例”。集合标题作为前端 i18n 文案接入项目现有语言文件；用户要求的中文名称保持为“视频模型示例”。

后端集中识别样例任务并执行访问策略，不能只依赖前端隐藏：

- 列表、图库和单任务详情仅向仍具有管理员角色的任务所有者返回样例任务。
- 素材内容仅向仍具有管理员角色的任务所有者提供。
- 普通任务删除接口拒绝删除样例任务，避免留下失去记录的托管文件。
- 样例删除只能经过专用管理员回滚接口，以便任务记录与文件一起处理。

集合行为：

- 只在当前管理员拥有该集合时显示。
- 若素材所有者之后失去管理员角色，集合与素材地址立即不可见、不可读，文件和记录保留供受控恢复或回滚。
- 支持预览、下载和拖入画布。
- 从画布删除节点不会删除素材任务或文件。
- 不出现在公开文档、匿名页面或普通用户图库中。
- 不提供跨用户分享或公开链接。

### 5.5 回滚

导入过程输出一份不含凭据的结果清单，记录：任务 ID、生产副本文件名、大小和 SHA-256。回滚只能依据该清单删除本次创建的任务记录和生产副本。

回滚不得：

- 删除原始测试文件。
- 按目录或通配符清空素材。
- 修改其他任务记录。
- 删除任何用户上传或生成的素材。

## 6. 错误处理

### 6.1 文档加载

- 文档语言文件请求失败时显示当前页面已有的错误状态，并提供重试。
- 切换语言期间保留稳定页面尺寸，显示加载状态，不回显上一语言正文。
- 本地存储值非法时忽略并重新执行语言映射。

### 6.2 素材导入

- 非管理员：返回 403。
- 不支持或伪造的媒体格式：拒绝导入且不留文件。
- 超过大小限制：拒绝导入且清理临时文件。
- SHA-256 不一致：拒绝导入且清理临时文件。
- 相同校验和已经存在：返回既有任务，标记为未新建，不重复写文件。
- 并发导入相同校验和：利用确定性任务 ID 唯一约束收敛到同一任务；失败请求清理自己的临时文件。
- 文件写入成功但数据库写入失败：删除本次生产副本。
- 数据库记录已存在但文件丢失：返回明确冲突，不静默判定为成功；由管理员先修复或执行受控重导。

## 7. 验证策略

### 7.1 文档自动检查

增加文档一致性检查，至少验证：

- 三份文档都存在。
- 三份文档包含相同的公开视频模型 ID 集合。
- 视频价格表的模型、计价单位和最终价格一致。
- `/v1/models`、`POST /v1/videos`、`GET /v1/videos/{task_id}` 和 `GET /v1/videos/{task_id}/content` 路径一致。
- 请求字段、任务状态和终态集合一致。
- 所有 JSON 代码块均可解析。
- 禁止词、已知内部标识、邮箱、疑似真实 Key 和内部域名扫描结果为空。

自然语言标题和段落不要求逐字对应。

### 7.2 示例测试

- 对 PowerShell、shell、Python 和 Node 示例执行静态语法或抽取检查。
- 通过本地模拟 API 跑通创建、处理中、完成、失败和下载流程。
- 确认轮询逻辑有次数或时间上限。
- 确认示例不会在处理中重新创建任务。
- 确认日志不会打印完整 API Key。

### 7.3 页面和截图检查

使用 Playwright 检查桌面和移动视口：

- 首次语言映射。
- 手动切换和刷新后的记忆。
- 三种语言的目录、标题、表格、代码块和长模型名。
- 截图加载、尺寸和替代文本。
- 无重叠、溢出或异常布局移动。

截图另做文件名、元数据、OCR/可见文字和像素级人工检查，确认没有真实账号、余额或 Key。

### 7.4 素材测试

后端测试覆盖真实行为：

- 管理员可以导入合法 MP4。
- 普通用户不能调用导入接口。
- MIME 伪造、非法 MP4、过大文件和校验和错误被拒绝。
- 相同校验和重复导入返回同一任务且不重复计费。
- 管理员可以列出、播放、Range 请求和拖入自己的样例素材。
- 其他用户不能列出或读取管理员样例素材。
- 样例素材所有者被降权后不能列出或读取样例素材。
- 导入失败不会遗留文件或任务。
- 回滚接口不能删除普通任务、其他管理员任务或原始源文件。

所有新增或重写的 Go 测试使用 `testify/require` 和 `testify/assert`，并保持 SQLite、MySQL 和 PostgreSQL 兼容。

生产导入前后分别核对 10 个文件的数量、大小、MIME、可播放性和 SHA-256。生产副本必须与原始文件逐一匹配。

### 8.1 上线前

1. 构建前端和后端。
2. 运行文档一致性、前端、后端和 Playwright 验证。
3. 扫描 Git 变更和构建产物中的敏感信息。
4. 构建新的不可变镜像并记录镜像 ID。
5. 不修改或停止当前生产容器。

### 8.2 热切换

1. 在备用容器名和备用端口启动候选容器。
2. 将候选容器加入 Caddy 使用的稳定别名网络。
3. 在切换前验证健康检查、三语言文档、价格、任务 API和管理员素材权限。
4. 仅在候选容器全部通过后切换稳定网络别名或重新加载 Caddy 配置。
5. 切换过程中当前生产容器保持运行。
6. 验证公网无 502、静态资源指纹正确、文档和 API 正常后，旧容器继续保留为回滚基线。

### 8.3 生产素材导入

热切换稳定后再执行素材导入，避免把代码切换和数据导入混成一个不可区分的故障点。导入按单文件执行并记录结果；任何一项失败立即停止后续导入，已成功项目保持可核对状态，不执行目录级清理。

### 8.4 上线后检查

- 三个文档 URL 均返回 200。
- 语言切换和本地记忆正常。
- 公开价格与生产价格接口一致。
- `seedance-2.0` 示例请求符合生产协议。
- 管理员看到且只能看到 10 个样例视频。
- 普通用户无法访问管理员素材。
- Caddy 和应用日志无本次切换导致的 502 或持续错误。

本次主要修改文档、展示和管理员样例导入。若视频接口实现未改变，则复用已有 10 个真实成功结果作为真实生成证据；只有接口实现发生变化时，才额外消耗额度执行一次 `seedance-2.0` 真实生成。

## 9. 完成标准

以下条件全部满足后才可宣告完成：

1. 三份文档已发布且新手可从零完成首次视频生成。
2. 三份文档技术事实一致，隐私扫描无命中。
3. 文档页面语言选择和记忆在桌面、移动端均通过验证。
4. 截图完全使用虚构数据且无敏感元数据。
5. 10 个指定视频原文件仍在原位置，生产副本校验和完全一致。
6. “视频模型示例”只对导入管理员可见，可预览、下载和拖入画布。
7. 普通用户素材、任务和余额未被修改。
8. 生产通过不停机热切换上线，无 502，并保留准确回滚容器。
