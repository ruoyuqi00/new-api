## Cause and change

The common response audit helper recognized `response.model`, `model`, `message.model`, and `session.model`, but omitted the Gemini `modelVersion` field. Streaming Gemini responses already use the shared scanner, so adding `modelVersion` capture fixes that path. Non-streaming native Gemini, Gemini-to-Chat/Claude, and Gemini-to-Responses handlers also omitted the capture call before response conversion; these three calls are now added.

Only four lines of production logic change. The response bytes, token accounting, model mapping configuration, model selection, billing, schema, frontend theme/effects, and customer/admin privacy rules are unchanged. The first non-empty returned model is recorded with the existing length limit. Missing, empty, and non-string returned model values remain absent. Old logs whose upstream model was never recorded cannot be reconstructed from this change.

Read-only production observation found recent non-streaming `/v1beta/models/gemini-3.8-flash:generateContent` logs on channels 2622 and 2486 with no actual response model recorded. This confirms the log-data gap; it does not establish that those upstreams return modelVersion, because their original response bodies were not retained.
