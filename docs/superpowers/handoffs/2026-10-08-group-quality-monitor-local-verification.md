# 分组降智监测：本地验收

2026-10-08，Asia/Shanghai。

新增 `/quality-monitor` 和左侧“降智监测”。管理员可创建按分组运行的间隔探测计划，仅支持 `gpt-6-astra` 和 `gpt-6.1-sol`，自定义问题、参考答案、匹配方式、思考强度、输出预算及超时，开启、暂停或立即运行。历史保存题目、实际答案、状态、耗时和命中渠道。普通用户仅能查看已发布且自己可用分组的结果，服务端剔除内部渠道、实际模型、诊断和估算费用字段。

## 使用

进入“降智监测 → 监测计划 → 创建计划”，选择分组和模型，填写题目及间隔分钟，保存后点击“立即探测”。新计划默认暂停且不发布；编辑已有计划可以开启定时探测和结果发布。人工评估保留答案供查看，精确匹配和包含匹配使用参考答案判断。

分组按执行时有效渠道、协议、优先级和权重选择，分组名称和渠道未写死。已移除分组的旧计划仍可暂停、修改和取消发布。不支持的组合记录为跳过。监测使用现有 OpenAI Compatible Responses 适配器，Codex 专用适配器因无法保留输出预算而跳过。监测请求可能产生上游费用，但不扣用户/API Key 余额，不计入普通消费日志、用量看板或渠道用量。

## 存储和发布边界

新增计划/结果表加入常规及快速迁移。最大题目配置和手动执行的完整快照可能超过 MySQL TEXT 容量，因此计划 QuestionsJSON 与既有 `system_tasks.payload` 在 MySQL 使用 LONGTEXT，PostgreSQL/SQLite 仍为 TEXT；既有 task State/Result 不变。最大配置保存、手动入队、持久化读取和解码回归，以及 MySQL/PostgreSQL DDL 生成检查通过；尚未连接真实 MySQL/PostgreSQL 验证迁移。

生产发布须在用户看过本地界面并确认后单独进行。发布前应检查生产 `system_tasks` 表体积及列扩容的锁表影响，不能把 SQLite/DDL 检查当作生产迁移验证。
