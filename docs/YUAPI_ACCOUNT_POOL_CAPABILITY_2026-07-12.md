# YuAPI 账号池能力说明（2026-07-12）

## 用户侧契约

普通用户仍然只选择分组和模型。渠道、账号池、账号凭据以及上游地址都是管理员资源，不进入用户请求参数，也不向普通用户展示。

```text
用户分组 + 模型
  -> 选择可服务该分组和模型的渠道模板
  -> 按用户分组 + 适配器类型选择账号池
  -> 按优先级、权重、并发、冷却和过期时间选择账号
  -> 使用账号自己的凭据、Base URL 和模型映射请求上游
```

## 路由规则

- 账号池必须指定用户分组和适配器类型。
- 默认不需要绑定渠道；未绑定时，账号池按用户分组和适配器类型自动匹配。
- 渠道绑定是可选的高级限制。存在绑定时，该账号池只会接管指定渠道。
- 账号没有填写 Base URL 或模型映射时，继承选中渠道模板的配置。
- 没有匹配账号池时，传统渠道继续使用自己的 Key 或 Multi-Key，不受影响。
- 启用的账号池至少需要一个账号，避免空池接管请求后造成生产故障。

## 导入能力

管理端支持以下导入来源：

- 直接粘贴，每行一个凭据；
- 单个或多个 TXT 文件；
- 单个或多个 CSV 文件；
- 单个或多个 JSON 文件或直接粘贴 JSON 数组。

CSV/JSON 可使用 `name`、`credential`、`api_key`、`key`、`type`、`base_url`、`model_mapping`、`priority`、`weight`、`concurrency_limit` 和 `cooldown_seconds` 字段。导入先生成逐行预览；凭据、OAuth JSON、Base URL 和模型映射通过校验后才能加入表单。

## 数据与安全

- 本次只迁移 Sub2API 的通用账号池能力，不迁移任何旧账号、密钥或生产凭据。
- `provider_accounts` 增加账号级 `base_url` 和 `model_mapping`。
- `account_pools` 增加 `adapter_type`，用于无渠道绑定时的自动匹配。
- 凭据不会出现在列表和详情响应；编辑时留空表示保留原凭据。
- 表结构继续由 GORM `AutoMigrate` 管理，查询兼容 SQLite、MySQL 和 PostgreSQL。

## 暂不包含

Kiro、Windsurf 等 Sub2API 专属协议适配器不属于通用 API Key 账号池。它们需要独立迁移协议实现、凭据刷新、代理和健康检查逻辑，不能通过导入账号配置替代。
